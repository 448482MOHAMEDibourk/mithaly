Terminology — Mithaly / مُعجم المصطلحات
======================================

هدف هذا الملف توحيد المصطلحات المستخدمه في المشروع (الإنجليزية/العربية) وتقديم مرجع سريع للمطورين الجدد.

- Layer / طبقة: التقسيم المعماري الرئيسي الذي يحتوي مسؤوليات واضحة وقابلة للعزل. في Mithaly نستخدم "طبقات" للدلالة على: `gaps`, `planning`, `execution`, `feedback`.
- Component / مكوّن: عنصر برمجي أصغر داخل طبقة (مثلاً: `GapAnalyzer` داخل طبقة `gaps`).
- Module / موديول: مكوّن برمجي صغير داخل `modules` أو `src/mithaly/core` يقدم واجهة محددة.
- Specialist / أخصائي: خدمة/وحدة تُسجل لدى المحرك لتقديم مهام محددة (مثلاً: `DebuggerSpecialist`).
- Artifact / أثر: ملفات المشروع الناتجة (README, metadata, code, data).

ملاحظات توجيهية للمطورين:

- يُنصح استخدام المصطلح "طبقة" في الوثائق والـ CLI والـ docstrings لانتظام المصطلحات في الكود والمستندات.
- استخدم "مكوّن" أو "موديول" عند الإشارة إلى عناصر داخل طبقات عندما تكون التفاصيل أصغر.
- راجع الدستور التفصيلي للنظام لـسياسات السلوك: `docs/MITHALY_CONSTITUTION.md`.

مثال سريع لسير العمل المتعلقة بالمسميات:

1. عند تسجيل وظيفة تقدم خدمة عبر المحرك (مثلاً محلل أخطاء)، عرفها كـ `Specialist` أو `Layer` بحسب نطاقها.
2. عند وصف واجهة برمجية صغيرة داخل طبقة، رتبها كمكوّن/موديول تحت `src/mithaly`.
3. سجّل الآثار الناتجة (تقارير، لقطات، تذاكر) كـ `Artifact` واحتفظ بها مؤقتًا في `docs/` حتى تُوسم بالثقة وتمدّد إلى KB.

هذا الملف موجز — إن رغبتَ، أستطيع توسيعه بفصل مصطلحات إنجليزية إضافية، أمثلة على التسجيل عبر `LayerRegistry`، أو نماذج docstring موحّدة.
